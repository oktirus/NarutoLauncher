# Архітектура та методологія процедурного Canvas 2D рендерингу технік чакри (Android TV)

## 1. Огляд та призначення
У проєкті Naruto TV Launcher (`NarutoLauncher/native-parity`) реалізовано повністю нативний рендеринг процедурних анімацій чакри для Android TV на чистому Android SDK (Java 17 + Custom Views/Canvas 2D без WebView, Compose чи сторонніх бібліотек).

Цей документ фіксує архітектуру рендерингу, вирішення критичних апаратних проблем графічного конвеєра Android та правила досягнення 1:1 паритету з веб-еталоном (`NarutoLauncher/prototype/technique-art.js` та `prototype/techniques.js`).

---

## 2. Багатошарова архітектура рендерингу техніки

Для кожної техніки у `TechniqueRenderer.java` реалізовано композитний конвеєр з 4 візуальних шарів:

```
[ Шар 4: Спекулярні відблиски та сателіти ] -> Білий відблиск на склі (#fff5e4), мікро-вихор супутник
[ Шар 3: Зовнішні орбітальні вихори ]       -> 18 ексцентричних еліпсів поля чакри, пульсуючі кільця
[ Шар 2: Центральне художнє тіло ]         -> Обертова платівка з м'яким синусоїдальним диханням
[ Шар 1: Внутрішній конвеєр вихору (Core) ] -> 23 зустрічні високошвидкісні дуги чакри на кривих
```

### 2.1. Чому розділення критично важливе
У першій ітерації перенесення спостерігалися дві крайнощі:
1. **Перевантаження (Wireframe Clutter):** Векторні заглушки з раннього прототипу (`techniques.js`) малювалися товстими непрозорими лініями поверх художньої картини, створюючи брудний каркасний вигляд.
2. **"Картонність" (Static Flat Sticker):** При повному відключенні векторних шарів і залишенні лише обертової текстури техніка виглядала як мертва пласка наліпка, позбавлена магії живої чакри.
3. **Ідеальний баланс 1:1:** Текстура служить насиченим тілом, а тонкі напівпрозорі дуги чакри (23 у ядрі + 18 на орбіті) створюють безперервний вихор енергії.

## 3. Критичні апаратні пастки конвеєра Android

### 3.1. Пастка втрати точності Float32 (Апаратне застигання анімації)
- **Симптом:** Візуально техніка виглядає правильно, але анімація обертання або повністю стоїть на місці, або смикається раз на кілька секунд. При цьому розмір відео та лічильники SurfaceFlinger показують рух.
- **Першопричина:** `ChakraFocusView` передавав Epoch-час `System.currentTimeMillis()` ($\approx 1.76 \cdot 10^{12}$ мс). При множенні на швидкість кут обертання досягав:
  $$\text{rot} = (\text{float})\, \text{Math.toDegrees}(t \cdot \text{speed}) \approx 82\ 823\ 058\ 882^\circ$$
  Тип `float32` (який приймає `canvas.rotate(float)`) має лише 24 біти мантиси. При значеннях порядку $8 \cdot 10^{10}$ мінімальний крок дискретизації становить **8192 градуси**. Зміна кута за 16 мс ($0.75^\circ$) в арифметиці float32 дає точний нуль:
  $$82\ 823\ 058\ 882.0\text{f} + 0.75\text{f} = 82\ 823\ 058\ 882.0\text{f} \quad (\Delta = \mathbf{0.000000})$$
- **Обов'язкове архітектурне рішення:**
  1. Відлік часу вести **суворо від моменту створення/старту View**:
     ```java
     long uptime = android.os.SystemClock.uptimeMillis();
     if (animationStartTime == 0) animationStartTime = uptime;
     long now = uptime - animationStartTime;
     ```
  2. Будь-які кутові величини загортати за модулем 360 у `double` **ДО** приведення до `float`:
     ```java
     float rot = (float) ((Math.toDegrees(t * speed)) % 360.0);
     ```

### 3.2. Емуляція `shadowBlur` без втрати Hardware Acceleration
- У HTML5 Canvas неон будується через `ctx.shadowBlur` та `ctx.shadowColor`.
- В Android метод `Paint.setShadowLayer()` при апаратному прискоренні або ігнорується, або вимагає перемикання на програмний шар (`LAYER_TYPE_SOFTWARE`), що викликає падіння FPS з 60 до 15 на процесорах TV.
- **Рішення — трипрохідний Neon Stroke:**
  1. *Ореол:* ширина $(3.0w + 0.032r) \cdot \text{dScale}$, alpha 38%, колір сяйва.
  2. *Тіло:* ширина $2.2w \cdot \text{dScale}$, alpha 85%, колір основи.
  3. *Ядро:* ширина $\max(0.6, w) \cdot \text{dScale}$, alpha 115%, розпечений білий колір.

### 3.3. Zero-Allocation у 60 FPS циклі
- Усі геометричні примітиви (`Path`, `RectF`, `float[]`) попередньо виділені у полях `TechniqueRenderer`.
- Заборонено оператори `new` у методах `onDraw()`, `drawTechnique()`, `drawSpiral()`, `drawTomoe()`.
- Очищення через `.reset()`, налаштування координат через `.set()`.

## 5. Протокол верифікації
1. **Збірка:** `Build.ps1` (48/48 unit-тестів пройдено, Android Lint — 0 помилок).
2. **Фізичний запис:** `screenrecord --time-limit 4` на Lenovo Android TV 14 (`192.168.100.26:5555`).
3. **Попіксельний аналіз:** локальний ROI сфокусованої картки (58 750 px), фільтр шуму H.264 ($\Delta > 10$), контроль спектра кольорів.
