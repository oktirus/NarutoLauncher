# Методологія 1:1 перенесення технік Canvas/JS у нативний Android Canvas (Zero-Allocation & Parity)

## 1. Контекст та проблема
У проєкті Naruto TV Launcher еталонний веб-прототип містить дві взаємопов'язані системи малювання технік:
1. `prototype/techniques.js` — базова процедурна векторна геометрія (спіралі, кола, томое, полум'я, кунаї), яка спочатку створювалася як тимчасова/процедурна візуалізація.
2. `prototype/technique-art.js` — фінальний художній рушій (Revision 18/26), який:
   - Для процедурних технік (`chidori`) повністю реалізує унікальний процедурний Canvas-алгоритм (`electricity()`).
   - Для художніх пластин (`completePaintings`: `rasengan`, `sharingan`, `kurama`, `fireball`, `amaterasu`) використовує високоякісні текстури `effect-*.webp` із суворими параметрами дихання, швидкості обертання та спекулярних відблисків.
   - `baseDraw` з `techniques.js` викликається **виключно** як fallback, якщо растрова текстура ще не завантажилася (`if (!loaded[id]) baseDraw(...)`).

Помилка першої нативної реалізації полягала в тому, що векторний fallback із `techniques.js` накладався ПОВЕРХ або ПІД текстуру `technique-art.js`, що створювало кашу, подвійне обертання з різними швидкостями, неправильні товщини ліній та спотворювало художній стиль.

## 2. Золоті правила перенесення 1:1

### Правило 1: Розділення еталону на Архітектуру та Fallback
- Завжди перевіряти `completePaintings` та `proceduralEffects` у `technique-art.js`.
- Якщо техніка є у `completePaintings`:
  - Коли бітмап завантажено (`bmp != null`): малюється суворо алгоритм `technique-art.js` (точна кутова швидкість `rotate`, масштабування `size = r * 2.46 * (1 + sin(t * 1.5) * 0.016 + energy * 0.035)`, альфа `0.84`, спекулярні відблиски).
  - Жодних зайвих векторних ліній із `techniques.js` поверх готової художньої пластини!
  - Коли бітмап відсутній (`bmp == null`): малюється векторний fallback із `techniques.js`.
- Якщо техніка процедурна (`chidori`):
  - Повне 1:1 математичне відтворення формул шумів, розрядів, вилок та ковзних імпульсів заряду.

### Правило 2: Емуляція HTML5 Canvas `shadowBlur` через 3-прохідний Neon Stroke
Апаратний Canvas Android не підтримує динамічний `setShadowLayer` без суттєвих втрат продуктивності або відключення апаратного прискорення. Для досягнення повного неонового ефекту HTML5 Canvas (`shadowBlur + dual stroke`) використовується трипрохідний рендеринг:
1. **Зовнішній розмитий ореол:** розширена лінія з низькою альфою (35-40%), колір сяйва (`#67c7ff`).
2. **Внутрішнє тіло розряду/елемента:** середня лінія з насиченим кольором (80-85%), колір тіла (`#459cff`).
3. **Розпечене ядро:** тонка білосніжна лінія (`#ecfbff`, `#ffffff`) з максимальною яскравістю (100-115%).

### Правило 3: Суворий Zero-Allocation у 60 FPS циклі
- Заборонено створювати об'єкти (`new Path()`, `new RectF()`, `new float[]`, `new Paint()`) всередині методів `onDraw` та `drawTechnique`.
- Усі контури, масиви координат, буфери точок виділяються як поля екземпляра класу `TechniqueRenderer`.
- Для очищення контурів використовувати `.reset()`, для прямокутників — `.set()`.

### Правило 4: Точна квантизація часу та Procedural Noise
- Якщо в JS використовується `tick = Math.floor(t * 24)`:
  У Java використовувати `long tick = (long) Math.floor(t * 24.0);`.
- Формула шуму:
  `double noise(double n, long tick) { double v = Math.sin(n * 127.1 + tick * 311.7) * 43758.5453; return v - Math.floor(v); }`
  Повинна збігатися з JS до кожного знака після коми.

### Правило 5: Енергетичні хвилі вибору (`burstLife`)
- Колір: згідно з `api.list.find(id).color`.
- Товщина: `1.2dp`.
- Радіус: $R_{\text{burst}} = r \cdot (1.04 + (1.0 - \text{energy}) \cdot 0.14)$.
- Прозорість: $\alpha = \text{energy} \cdot 0.5 \cdot 255$.

## 3. Специфікація перенесення конкретних технік

| Техніка | Тип у `technique-art.js` | Швидкість обертання | Специфічні елементи |
| :--- | :--- | :--- | :--- |
| **Чідорі** (`chidori`) | Повністю процедурна | — | 22 конвеєри, 2 4-точкові вилки, біжучий імпульс заряду, 18 променів ядра |
| **Расенґан** (`rasengan`) | `completePaintings` | $t \cdot 0.82$ рад ($\approx 47^\circ/\text{c}$) | Чиста пластина $2.46r$, дихання $\sin(1.5t) \cdot 0.016$, альфа 214 |
| **Шарінґан** (`sharingan`) | `completePaintings` | $t \cdot 0.38$ рад ($\approx 21.8^\circ/\text{c}$) | Пластина $2.46r$ + білий спекулярний овал `#fff5e4` на $(-0.68r, -0.35r)$ під кутом $0.6$ рад |
| **Курама** (`kurama`) | `completePaintings` (mesh) | 0 (хвильова деформація) | Хвильова сітка $\sin(1.3t + 7y) \cdot 0.014n$, 9 процедурних коливальних хвостів |
| **Расенсюрикен** (`rasenshuriken`) | Платівка + `core` + `accents` | $t \cdot 2.05$ рад ($\approx 117.5^\circ/\text{c}$) | Радіальний градієнт стихії вітру + 23 зустрічні дуги чакри ядра (кліп $1.08r$) + платівка $2.46r$ + 18 орбітальних еліпсів ($2.4t$, кут дуги `toDegrees(a)`). **Категорично заборонено** малювати векторні леза чи спіраль поверх растрової платівки! Масштаб базового радіуса `baseR = 0.68 * emblemWidth` (для діаметра сюрікена 203 px на 768p). |

## 4. Швидке тестування та Parity Studio
- Перед встановленням APK на телевізор перевіряти техніку в ізольованій студії `NarutoLauncher/prototype/compare.html` (відкривається у браузері Orca).
- Студія показує 1:1 полотно еталона та Android-рендерера з автоматичним підрахунком розбіжності пікселів ($\Delta$). Допустима дельта для релізу: $< 0.05\%$.

## 5. Протокол верифікації
1. **Збірка та unit-тести:** `Build.ps1` (0 warnings, 0 failing tests).
2. **Встановлення на реальний Android TV:** `adb connect`, `adb install -r`.
3. **Запис фізичного відео 60 FPS:** `screenrecord` тривалістю 4 секунди.
4. **Математичний аналіз ROI картки (42 750 px):**
   - Відсікання артефактів H.264: поріг $\Delta > 10$.
   - Обчислення `Idle Mean Delta` та відсотка активних пікселів у зоні сфокусованого елемента.
   - Спектральний аналіз колірної гами.
