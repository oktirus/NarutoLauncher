# Themed TV Launcher

Створи придатний до використання Android TV / Google TV HOME застосунок, а не лише макет. Стиль визначає обраний твір та погоджені референси; технічна основа — Android Views + hardware-accelerated Custom Canvas, Java або Kotlin. Не відтворюй Naruto під іншою назвою. Для нового проєкту за замовчуванням починай нативно: вебпрототип потрібен лише як явно обраний інструмент дизайну або існуючий еталон міграції.

Скіл не містить готового Android проєкту й не гарантує результат одним запуском. Агент має реалізувати код, створити асети, зібрати APK та виконати доступні перевірки. Відсутні генератор, SDK, референси або пристрій позначай як конкретну межу; не називай заглушки готовою графікою чи локальний build встановленням.

## Маршрут роботи

1. **Визнач контекст.** Прочитай інструкції проєкту, стан Git, build, manifest, існуючі тести й документацію. Визнач режим: новий launcher, reskin зі збереженням поведінки, чи точне перенесення еталону. Не перезаписуй чужі зміни.
2. **Зафіксуй контракт.** Заповни [references/project-contract.md](references/project-contract.md). З'ясуй твір/версію, цільову платформу, обсяг, мову, стиль і наявний еталон. Запитуй лише те, що справді блокує результат; решту познач як припущення. Тему не вигадуй, якщо її не задано.
3. **Досліди стиль і канон.** Для графіки прочитай [references/art-direction.md](references/art-direction.md). Знайди й переглянь справжні кадри, зафіксуй походження та ролі референсів. Встанови палітру, типографіку, матеріали, мову іконок, композицію та допустимий рух. Для live-action не застосовуй автоматично anime cel shading.
4. **Зроби вертикальний зріз.** Працюючі Home, один якісний фон, іконки реальних установлених застосунків, фокус D-pad, запуск, Settings, Back і HOME setup. Перевір композицію на цільовому viewport/density до масової генерації асетів. Не підміняй прохання виконати роботу нескінченним плануванням чи погодженнями; уже затверджений стиль використовуй далі.
5. **Реалізуй контракт.** Прочитай [references/native-engineering.md](references/native-engineering.md). Відокрем тему/каталоги асетів від механіки лаунчера. Перший завершений зріз задає стандарт для решти сцен, ефектів і панелей. Додаткову гру роби лише якщо вона входить у завдання.
6. **Для порту з вебу** додатково прочитай [references/visual-parity.md](references/visual-parity.md). Еталон — погоджений runtime, а не старий native preview. Спочатку простеж реальні render branches, включно з fallback, потім переносиш формули й асети.
7. **Перевір і достав.** Використай [references/verification-and-delivery.md](references/verification-and-delivery.md). Перечитай змінені виклики та diff, відтвори знайдені дефекти meaningful regression-тестами. Build, рендер, емулятор, фізичний TV, акустичне прослуховування і RAM — різні рівні доказів.
8. **Перед прийманням** звір [references/failure-catalog.md](references/failure-catalog.md) із виконаним scope. Не додавай відсутні фічі лише заради цього каталогу. Залиш конкретні TODO лише для неперевіреного/незавершеного, без заяви «100% готово» поверх них.

## Обов'язкові властивості результату

- Впізнаваність твору спирається на дизайн персонажів, реквізит, матеріали та ритм композиції, а не на випадковий логотип поверх generic UI. Уся серія асетів узгоджена.
- D-pad/OK/Back працюють без миші. Видимий фокус відповідає елементу, який одержить OK: у доку, бібліотеці, settings, dropdown, діалогах і грі, якщо вона є.
- Обрані застосунки можна додати, прибрати **і переставити** пультом. Сітки й док реагують на доступну ширину та кількість карток.
- У каталозі навігаційних ефектів — **статичні прев'ю**. Рух у live-фокусі залежить від налаштування та lifecycle. Вимкнений рух не прибирає індикатор вибору.
- Якщо звук підтвердження вимкнено — запуск застосунку негайний. Якщо увімкнено — завершення короткого cue, потім запуск; відмова/зависання аудіо не блокує Home. Back скасовує очікування.
- Ambient показує один погоджений набір контенту без дублювання годинника/доку/заголовка. Повернення відновлює Home і правильний фокус.
- HOME setup: пропозиція на першому запуску та постійний пункт у налаштуваннях зі статусом. Після самої установки APK не намагайся запускати Activity у фоні; запитуй системний вибір з видимого застосунку. Не призначай HOME тихо і не відключай штатний launcher.
- Великі зображення, ефекти, спрайти та аудіо мають визначеного власника, обмежений кеш і перевірені close/pause/resume/trim шляхи.

## Обсяг, повноваження й повторне використання

Запит створити launcher дозволяє локальну реалізацію та збірку. Він не означає дозвіл змінити фізичний телевізор, його основний HOME, опублікувати, зробити commit/push або очистити інші проєкти. Виконуй live-кроки, коли target і дія вже прямо авторизовані; не проси повторно той самий дозвіл. Для незалежного агента/review застосовуй наявні правила делегування; не запускай агентів автоматично.

За доступності використовуй imagegen для генерації/редагування та прочитай його інструкції. Спеціалізований anime-art skill доречний лише для відповідної естетики. Скіл самодостатній: відсутність попереднього NarutoLauncher чи інших скілів не має блокувати новий проєкт. Не копіюй старі IP, package ID, ключ підпису, персонажів, кількість сцен, точні PSS-значення чи test count як налаштування нового.

## Що віддати користувачу

Вихідний код, runtime-асети й оригінали генерацій, джерела референсів/промпти, відтворювану збірку, APK з hash/версією, коротку інструкцію встановлення й відкату, звіт фактичних перевірок і меж. Для передачі іншому агенту підготуй переносний пакунок без абсолютних залежностей від цього ПК, приватних даних, кешів build та зайвих відеодублікатів.
