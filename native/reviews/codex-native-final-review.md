# Codex: фінальна локальна перевірка Native Preview

Дата: 09.11.2026, Europe/Kyiv. Координатор самостійно перевірив і виправив код після авторської реалізації та незалежного рев'ю Antigravity.

**Оновлення після окремого доручення користувача:** preview встановлено на Lenovo та виміряно Home PSS. [Живий звіт](lenovo-native-memory-20261109.md): v26 — 232,30 МіБ, native після навігації — 61,48 МіБ; HOME залишено v26. Межі нижче описують початкове локальне рев'ю; повне TV-приймання, музичні/ігрові сценарії й sleep/wake залишаються відкритими.

**Вердикт: локальні перевірки пройдені; кандидат готовий до окремого приймання на Android TV.** Повний візуальний паритет із v26, PSS, реальний звук і GPU timing цим вердиктом не підтверджуються. Пристрій, HOME і встановлена вебверсія в цьому етапі не змінювалися.

Поточний APK: [KonohaNative-1.0.0-debug.apk](../releases/KonohaNative-1.0.0-debug.apk). Точні SHA256, розмір і staging наведено у [маніфесті](../releases/build-manifest.json) та [машинній перевірці кандидата](../verification/candidate-verification.json). Пакет `ua.konoha.tv.nativepreview`, versionCode 1, minSdk 26, targetSdk 34, debug signing. У маніфесті є LAUNCHER / LEANBACK_LAUNCHER; HOME не додано.

## 1. Чому попередній PASS був недостатнім

Перевірено авторський APK `FD065302F1F1054ABB9EE4F700B05D219C86C15E2F3C6165D158B892C519620F`: джерела збігалися зі staging, усі 98 ресурсів — з APK. Цей APK та його джерела збережені у `codex-final-evidence/before/`; контрольні суми — у `codex-final-evidence/before.json`. Це окремий незмінений кандидат агента, а не поточний APK.

Нові тести на коді агента відтворили дві помилки: вибір шпалер втрачав executor після trim, пошук забирав фокус із поля введення. Результати: [NativeLifecycleTest-red.xml](codex-final-evidence/before/NativeLifecycleTest-red.xml). Розширений аудіостенд на його AudioController відтворив звернення fade callbacks до вже звільненого плеєра: [audio-red.log](codex-final-evidence/audio-red.log).

Отже, історичний `antigravity-final-review.md` підтверджує виконані агентом перевірки його кандидата, але не закриває ці прогалини і не є поточним прийманням. Історичні звіти та `codex-v1-evidence/` залишено без змін.

## 2. Виправлення координатора

| Область | Проблема й виконане виправлення | Перевірка |
|---|---|---|
| Живі панелі після trim | `MainActivity.onTrimMemory` викликав остаточний `ScenesPanel.release`, після чого повторний render використовував завершений executor. Додано багаторазовий `clearCache`, повторний render активної панелі та відновлення слухачів прев'ю технік. | Два послідовні trim + pause/resume на виробничій Activity; picker залишається доступним. |
| Кеш технік | Закриття вибору не звільняло спільні пластини всіх технік. `platesFor` визначає набір активної техніки; закриття й зміна техніки скасовують старі декодування та відкидають зайві зображення. Для Гамабунти зберігаються idle/jump. | Відкриття, decode, trim, закриття й повторне відкриття; перевірено склад кешу. |

| Аура бібліотеки | Непрозорий фон карток закривав нижній шар чакри; бібліотека не отримувала власний lifecycle pause. Зроблено прозорий фон карток і pause/resume її шару ефектів. | Програмний рендер бібліотеки; lifecycle підключений у MainActivity. |
| Адаптивні сітки | Зменшення columnCount на вже виміряній GridLayout могло викинути IllegalArgumentException; переобчислення в onSizeChanged залишало старі розміри до наступного measure. `PickerGrid` скидає матеріалізовані позиції, а ширини перераховуються до super.onMeasure. ## 4. Виконані перевірки

- `Build.ps1`: JUnit + lintDebug + assembleDebug успішні в ASCII staging, указаному у build-manifest.json.
- **48/48 JUnit**, 0 failures/errors/skipped: 14 physics, 10 preferences, 6 HUD, 5 grid helper, 4 catalog, 7 lifecycle, 2 rendering.
- **12 груп аудіосценаріїв** з production AudioController проти контрольованих JVM-підмін Android media/Handler. Фікстура 12 с має fade 3 с; фікстура 20 с перевіряє повні 3.5 с.
- **Lint: 0 Fatal / 0 Error**, залишкові warnings перелічені в native-lint.xml. Наявність warnings не прихована.
- **780/780 baseline v26**: [лог](codex-final-evidence/v26-baseline.log). Координатор не редагував prototype/ або android/.
- **136 файлів app/src** відповідають фінальному staging; **98/98 активів** відповідають asset-manifest.json та вмісту APK; Robolectric відсутній у DEX. Перевірено скриптом verify_candidate.py.
- APK Signature Scheme v2 перевірено apksigner; minSdk/targetSdk/package підтверджено aapt. [Метадані](codex-final-evidence/apk-metadata-verification.txt).
- **16 PNG програмного Skia-рендеру** у [verification/native-ui](../verification/native-ui/): Home 1366/1920, бібліотека, сцени, техніки, гра, налаштування; три сітки додатково при 390/1280/1920 px. Оглянуто головні екрани та компактні сітки. Прокрутка є штатною для карток, що не вміщаються по висоті.

Robolectric 4.14.1 додано лише як testImplementation. Тести виконують production Activity/Views на API 28 із native software graphics, керованим vsync і Looper; вони не замінюють API 34 на Android TV. Початкові невдалі спроби підключити інший runtime та діагностика vsync залишені в evidence, але не зараховані як продуктова регресія. Червоні регресійні докази вище стосуються конкретних assertion failures, а не помилок середовища.

## 5. Що залишається для завершення міграції на TV

1. Окремий живий тест preview на підтвердженому Lenovo: холодний старт, повернення з застосунків, D-pad/Menu/Back, sleep/wake, пошук, зміна порядку, повторні цикли панелей і гри, rotation/ambient, trim та звуки. На цьому етапі ADB і пристрій не використовувалися.
2. Порівняти зовнішній вигляд і рух із v26 на тому самому екрані; локальні PNG підтверджують наявність інтерфейсу, але не точний анімаційний паритет.
3. Виміряти сумарний PSS процесів, graphics/GPU, CPU та час запуску у тих самих сценаріях і налаштуваннях: Home, усі picker, після багаторазової гри, музика on/off. Чисельна економія RAM наразі невідома.
4. Перевірити справжні confirm cues, відсутність чутного шва музики й поведінку аудіофокусу при зовнішньому застосунку; стенд не перевіряє Android decoder, AudioTrack або драйвер.
5. Перед реальною заміною HOME визначити спосіб перенесення налаштувань/обраного зі старого package та rollback. Автоматичного імпорту із sandbox вебверсії немає; API імпорту JSON є. Release signing / versioning і HOME залишаються окремим етапом продуктового розгортання.

Commit, push, публікацію, встановлення та зміну HOME не виконано. Після перевірок нові зміни продукту в межах цього рев'ю не плануються.
