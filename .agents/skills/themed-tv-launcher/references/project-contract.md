# Контракт нового лаунчера

Це шаблон робочого документа проєкту. Заповни його фактами та явно позначеними припущеннями; не змушуй користувача вручну відповідати на всі пункти. Для reskin не змінюй погоджену механіку без потреби. Для порту додай mapping еталон → native і перелік відмінностей.

## Ідентичність і середовище

| Поле | Що зафіксувати |
|---|---|
| Твір і версія | Назва, сезон/арка/екранізація, дизайн героїв, небажані спойлери |
| Призначення | Особистий TV, сімейний екран, виставковий kiosk; не змішувати режими |
| Режим роботи | Greenfield / reskin / порт існуючого UI |
| Візуальний авторитет | Погоджені кадри/малюнки або конкретна версія runtime |
| Платформа | Android TV/Google TV, API, ABI, RAM, viewport, density, overscan; APK не встановлюється на Tizen/webOS |
| Ідентичність APK | Унікальні applicationId, label, component, versionCode; підпис для майбутніх update |
| Мова | Українські рядки, правила назв і перекладів, fallback fonts |
| Доступні засоби | SDK/JDK/Gradle, генератор, browser/emulator, конкретний дозволений TV |
| Бюджети | Вимірювані цілі startup, frame time, Home/game/gallery PSS; базова збірка для порівняння |

У наявному проєкті не підвищуй minSdk/залежності без потреби. Для нового обирай API за цільовим обладнанням і потрібними можливостями, а не за старим прикладом. Фіксуй перевірені toolchain versions.

## Функціональна матриця

Статуси: required / optional / excluded. Для required вкажи екран, вхід пультом, дані, перевірку. Не перетворюй усі optional на обов'язкові.

| Можливість | Базова поведінка |
|---|---|
| Home | Фон, погоджений заголовок/цитата за потреби, один годинник, адаптивні застосунки |
| Реальні застосунки | TV/звичайні launch intents за контрактом, дедуплікація, fallback icon, відсутні packages обробляються без crash |
| Обране і порядок | Додати/видалити, режим переміщення OK/long-press/Menu → стрілки → OK; Back скасувати, порядок зберегти |
| Бібліотека | Усі доступні launchable apps, пошук/фільтр лише якщо потрібні, pin і повернення фокуса |
| Навігаційний ефект | Стиль твору, живий на активній картці, статичний каталог, motion-off доступний |
| Шпалери | Добірка різних сцен, прев'ю, назва, кадрування/точка фокуса; ротація опційна |
| Аудіо | Cue launch/focus, master і гучність; музика/crossfade лише за контрактом |
| Settings | Видимий фокус рядка/контролу, dropdown без подвійного курсора, HOME status/action |
| Ambient | Idle/ручний вхід, інший склад шарів, Back/OK повернення; не видавати за фізичне sleep |
| Мінігра | Лише за запитом: тематичні спрайти, повна ширина, пульт+видимі touch controls, pause/resume, best score |
| Persist/import | Схема й версія, atomic import, clamps/domains, nullable defaults, збереження після update |
| HOME setup | First-run suggestion + повторний пункт, cancel/Later, API/OEM fallback |

Не додавай декоративну кнопку пошуку/посилання, дрібний tagline чи debug status без користі. Тематична назва «застосунків» має залишатися зрозумілою: не називай їх бойовими техніками лише через тему. Годинник без зайвої плашки — добрий початковий варіант; контраст забезпечуй композицією і локальною тінню, а остаточний вигляд визначає brief.

## Тематичний словник

Створи таблицю `функція → назва в UI → мотив/предмет → обґрунтування з референсу`. Наприклад, для космічної історії бібліотека може нагадувати бортовий каталог, для фентезі — картотеку/артефакт, для детективу — архів справ. Не перенось сувої, чакру чи японські знаки у світ, де їх немає. Назви застосунків залишай впізнаваними.

## Артефакти проєкту

Доцільна структура, адаптуй до репозиторію:

```text
docs/brief.md                     # цей контракт
docs/style-bible.md               # стиль і правила
docs/asset-manifest.json          # джерела, оригінали, runtime, hashes
docs/acceptance.md                # матриця станів, результати, межі
art/references/                   # переглянуті джерела з provenance
art/originals/                    # схвалені генерації без runtime компресії
app/src/main/assets/             # лише потрібні runtime-файли
verification/<candidate>/        # потрібні JSON/log/еталонні кадри
releases/                        # APK + build manifest
```

Asset manifest: стабільний `id`, `kind`, relative `originalPath`/`runtimePath`, width/height, alpha, crop anchor/safe regions, reference URLs і роль, prompt/seed якщо доступний, hash, status. Зберігай промпт повністю; seed без підтримки генератора не вигадуй. Для іконки додай app mapping, для спрайта — baseline/poses/orientation, для ефекту — render mode та static preview.

Не імпортуй приватні preferences із чужого package автоматично. Документуй явний export/import або backup/restore та сумісність версій. Не вкладайте приватний signing key чи DPAPI backup у переносний source archive.
