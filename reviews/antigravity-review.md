# Незалежне ревю прототипу «Konoha — Naruto Launcher»

**Агент:** Antigravity  
**Об'єкт оцінки:** Інтерактивний веб-прототип лаунчера `NarutoLauncher/prototype/` (HTTP preview `127.0.0.1:8767/prototype/`)  
**Дата:** 7 листопада 2026 року  
**Межі оцінки:** Локальний інтерактивний прототип, графічні та звукові ресурси, візуальна естетика, навігація D-pad/клавіатурою/мишею, доступність і збереження вихідних файлів Yoru. Інсталяція APK на фізичні пристрої не перевірялась згідно з брифом.

### Ключові сильні сторони:
1. **Цілісність всесвіту та відсутність залишків мульти-аніме:** Проєкт повністю позбувся розрізненого калейдоскопу. Створено єдиний естетичний простір Конохи: вечірній захід сонця, місячна ніч та світанок виконані з єдиного ракурсу (Hokage Rock, дахи Конохи, Наруто в позі споглядання).
2. **Якість іконографіки:** 10 згенерованих емблем застосунків (`assets/runtime/*.webp`) — це не накладені логотипи на квадрати, а автентичні предмети спорядження ніндзя (сувій відтворення SmartTube, ліхтар Lampa з печаткою полум'я, кінострічка UAKino з синьо-жовтими талісманами, сюрикен Kodi з кристалом, жабка Spotify, капелюх-конус VLC). Усі мають чесний альфа-канал і виразні силуети.
3. **Безпека та ізоляція:** Надвисокий рівень гігієни коду: строгий CSP у `index.html:3`, відсутність зовнішніх CDN-залежностей, екранування через `escapeHTML` (`app.js:20`), збереження всіх 122 файлів Yoru без жодної бітової мутації (підтверджено `verification/yoru-before.json`).
4. **Аудіо- та життєвий цикл:** 5 оригінальних синтезованих WAV-звуків без використання чужого копірайтного OST; повага до browser autoplay policy (явна активація через «Увімкнути атмосферу»); коректна пауза фону й анімацій при згортанні вкладки (`visibilitychange` / `window.YoruPause`).

Водночас виявлено 2 дефекти пріоритету **P1** (помилка очищення координат сліду фокуса та розсинхронізація миші/клавіатури) та 4 зауваження **P2** (композиційне перекриття персонажа підписом, скидання фокуса при розкріпленні у фільтрі, статичність паралаксу на TV та наддрібні розміри шрифтів для 10-foot UI).

## 2. Підтверджені дефекти (P1 / P2 Findings)

### [P1-01] Залишковий стан `focusCenter` у `hideFocus()` викликає хаотичні спалахи чакра-трейлу через весь екран
- **Файл та рядки:** [prototype/app.js:161](file:///E:/файли/Робота/Network/NarutoLauncher/prototype/app.js#L161), [prototype/app.js:165-167](file:///E:/файли/Робота/Network/NarutoLauncher/prototype/app.js#L165-L167)
- **Симптом та відтворення:**
  1. Сфокусувати будь-яку картку в доці (наприклад, SmartTube або Spotify). `focusCenter` зберігає її екранні координати.
  2. Перевести фокус D-pad'ом вгору на панель сцен або вкладок навігації (викликається `hideFocus()`).
  3. Повернути фокус назад на будь-яку картку в доці (або закрити модальне вікно бібліотеки).
  4. На Canvas малюється довга дуга чакра-сліду (`trails.push`), яка тягнеться через половину екрана від старих застарілих координат до поточної картки.
  5. *Підтвердження на знімку:* На `verification/candidate-chakra-focus.png` чітко видно відірвану діагональну блакитну лінію, що тягнеться від даху біля Наруто вниз до іконки SmartTube.
- **Причина:** У функції `hideFocus()` (рядок 161) очищуються `focusTarget = null`, `#chakra-focus.hidden = true` та класи `.is-focus`, але змінна `focusCenter` **не скидається в `null`**. При наступному вході у функцію `updateFocus()` умова `if (focusCenter && canMove() && ...)` спрацьовує з координатами минулої активності.
- **Вплив:** Порушення візуальної плавності ключового ефекту фокуса (FC02); користувач бачить «артефактні блискавки» поверх пейзажу.
- **Мінімальне виправлення:** У `prototype/app.js` у функції `hideFocus()` додати `focusCenter = null;`, а також скидати `focusCenter = null;` при викликах `openPanel()` та `closePanel()`.

```javascript
// prototype/app.js:161
function hideFocus(){
  focusTarget=null;
  focusCenter=null; // <-- Додати скидання координатного центру
  $('#chakra-focus').hidden=true;
  $$('.app-card.is-focus').forEach(e=>e.classList.remove('is-focus'));
}
```

### [P1-02] Наведення курсору миші (`pointerover`) візуально переміщує чакра-кільце, але не синхронізує активний елемент клавіатури/пульта
- **Файл та рядки:** [prototype/app.js:172](file:///E:/файли/Робота/Network/NarutoLauncher/prototype/app.js#L172), [prototype/app.js:134-148](file:///E:/файли/Робота/Network/NarutoLauncher/prototype/app.js#L134-L148)
- **Симптом та відтворення:**
  1. За допомогою клавіатури або D-pad вибрати першу картку «SmartTube» (`document.activeElement` стає карткою SmartTube).
  2. Навести курсор миші на п'яту картку «Spotify».
  3. Чакра-кільце перелітає на Spotify, картка підсвічується класом `.is-focus`.
  4. Натиснути клавішу `Enter` або кнопку `OK` на пульті: замість Spotify запускається SmartTube!
  5. Якщо після наведення миші натиснути `ArrowRight`, навігація розраховується від `activeElement` (SmartTube) і переходить на другу картку (Lampa), ігноруючи те, на що вказувало кільце фокуса.
- **Причина:** Слухач `pointerover` (рядок 172) викликає лише `updateFocus(card)`, що маніпулює візуальним DOM-елементом `#chakra-focus`, але не викликає `card.focus()`. Відповідно, системний `document.activeElement` залишається на попередньому елементі.
- **Вплив:** Порушення специфікації FC04 («Та сама семантика фокуса для миші. Без втрати keyboard selection»). Критичний дисонанс керування в гібридних середовищах (AirMouse, тачпад, підключена миша).
- **Мінімальне виправлення:** У слухачі `pointerover` синхронізувати DOM-фокус:
```javascript
// prototype/app.js:172
document.addEventListener('pointerover',event=>{
  const card=event.target.closest('.app-card');
  if(card&&card!==focusTarget){
    card.focus({preventScroll:true}); // <-- Синхронізує activeElement без стрибка скролу
    updateFocus(card);
  }
});
```

### [P2-02] Втрата фокуса (`document.body`) при знятті закріплення («unpin») у режимі фільтра «Лише обране»
- **Файл та рядки:** [prototype/app.js:120](file:///E:/файли/Робота/Network/NarutoLauncher/prototype/app.js#L120), [prototype/app.js:93-96](file:///E:/файли/Робота/Network/NarutoLauncher/prototype/app.js#L93-L96)
- **Симптом та відтворення:**
  1. Відкрити модальне вікно бібліотеки («Застосунки»).
  2. Увімкнути кнопку «Лише обране» (`filterPinned = true`). У сітці відображаються лише закріплені застосунки.
  3. Перейти на будь-який застосунок і натиснути кнопку «Закріплено», щоб зняти його з обраного.
  4. Застосунок миттєво зникає з відфільтрованого списку через перемальовку `renderLibrary()`.
  5. Спроба відновити фокус `$$('[data-action="pin"]').find(b=>b.dataset.package===pkg)?.focus();` зазнає невдачі, бо елемента більше немає в DOM.
  6. Фокус падає на `document.body`. При наступному натисканні будь-якої стрілки D-pad алгоритм просторової навігації повертає фокус на перший елемент модального вікна — рядок пошуку `#app-search`, збиваючи позицію користувача в каталозі.
- **Вплив:** Дезорієнтація користувача при кастомізації обраного з пульта TV.
- **Мінімальне виправлення:** Якщо після `renderLibrary()` знята кнопка відсутня, переводити фокус на сусідню доступну кнопку в сітці, або на кнопку фільтра `[data-action="filter"]`.

### [P2-03] Фоновий паралакс повністю вимкнений при роботі з TV-пульта та майже непомітний на Desktop
- **Файл та рядки:** [prototype/app.js:173](file:///E:/файли/Робота/Network/NarutoLauncher/prototype/app.js#L173), [prototype/style.css:4](file:///E:/файли/Робота/Network/NarutoLauncher/prototype/style.css#L4) (`.backdrop`)
- **Симптом та відтворення:**
  1. Змінні зміщення паралаксу `--px` та `--py` оновлюються виключно у слухачі `pointermove`.
  2. На Android TV або при чистому керуванні з D-pad/клавіатури події `pointermove` не генеруються взагалі. Паралакс залишається абсолютно нерухомим (`--px: 0`, `--py: 0`).
  3. Крім того, формула в CSS: `translate3d(calc(var(--px)*.35px), calc(var(--py)*.35px), 0) scale(1.035)`. Оскільки максимальне значення `--px` становить ±10, максимальний фізичний зсув фону становить лише `±3.5px` на екрані шириною 1920px (менше 0.18% ширини екрана), що робить його майже невидимим для ока навіть при русі мишею.
- **Вплив:** Неповне виконання вимоги BG04 («Багатошаровий parallax... Рухається не лише backdrop scale»).
- **Мінімальне виправлення:** При зміні фокусу в доці (наприклад, перехід між 7 слотами) плавно транслювати `--px` від `-15` до `+15` залежно від індексу активної картки, а коефіцієнт зсуву в CSS збільшити з `.35px` до `1.5px` – `2.0px`.

## 4. Топ-3 художні пропозиції (у межах затвердженого задуму)

1. **Аудіо-візуальна пульсація ліхтарів та чакра-вогню в нічній сцені:**
   У нічній сцені (`konoha-night`) ліхтарі на вулицях села та синє чакра-полум'я всередині іконки Lampa наразі мають статичну або лінійну CSS-анімацію. Додавання ледь помітної нерівномірної органічної пульсації світіння (імітація теплого мерехтіння живого вогню під подихом нічного вітру) зробило б нічну Коноху ще затишнішою.
2. **Адаптація палітри та частинок Canvas під настрій сцени:**
   Зараз 28 листочків на Canvas мають однакові кольори (суміш вохри `#e9af67` та моху `#9bab72`) для всіх трьох періодів доби. Було б виразніше:
   - для світанку (`dawn`) — додати напівпрозорі смарагдові листочки та легкі краплі ранкового туману;
   - для вечора (`dusk`) — зберегти золотаво-вогняне листя та поодинокі іскри «Волі Вогню»;
   - для ночі (`night`) — змінити частинки на м'які іскри світлячків або синюваті пелюстки, що відбивають місячне сяйво.
3. **Мікродинаміка стрічок пов'язки Наруто:**
   Ілюстрація Наруто на даху виконана надзвичайно якісно. Проте кінці стрічок його протектора та край коміра виглядають абсолютно нерухомими, в той час як навколо них летить листя й пливуть хмари. Додавання ледь помітної синусоїдальної CSS-деформації або легкого коливання стрічок додало б фігурі життя без необхідності замінювати статичний фон важким відеофайлом.
