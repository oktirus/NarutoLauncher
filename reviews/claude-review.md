# Konoha — незалежне ревю (Claude)

Дата: 2026-11-07. Обсяг: інтерактивний прототип `prototype/` + assets + verification-скріншоти.
Метод: читання коду з рядками, візуальний огляд 5 candidate-скріншотів, icon-board та власних
скріншотів, живі перевірки в **ізольованій** сесії браузера `konoha-claude-review`
(1280×720, 960×540, reduced-motion емуляція; play() інструментовано для підрахунку звуків).
Звіт Antigravity не читав. Код, assets, AnimeLauncher, git — не змінювались.

## Вердикт

Візуально — сильний, цілісний кандидат: один світ Naruto, три сцени з ідентичною композицією
(crossfade не «стрибає» персонажем), 10 іконок одного матеріалу й світла, без multi-anime залишків.
Код компактний, escape/CSP коректні, Android-дії в макеті чесно позначені.

**Є 2 блокуючі (P1) дефекти взаємодії**, обидва відтворені в браузері, обидва з мінімальним фіксом.
Їх варто виправити до фінального макета. Решта — P2/P3.

## P1 — підтверджені дефекти

### P1-1. D-pad у налаштуваннях: `<select>` перехоплює ↑/↓ і мовчки змінює налаштування
- Код: `prototype/app.js:142-143` — для `SELECT` вертикальні стрілки змінюють `selectedIndex` і
  диспатчать `change` → `persist()` + `applyTimers()` (`app.js:129`). `app.js:137`: Enter на select нічого не робить.
- Відтворення (ContextMenu → 12× ArrowDown):
  `close → motion → audio → ambience → rotation(0) → rotation(60) → (180) → (600) → 600…`.
  У `localStorage` після проходу: `rotation: 0 → 600`.
- Наслідки: (а) пультом неможливо пройти вниз повз «Зміна сцен» — «Мить у Коносі», «Увійти в режим спокою»,
  «Налаштування Android», Wi-Fi, «Оновити», «Про Коноху» досяжні лише через ←/→ (DOM-порядок, `app.js:144`);
  (б) простий прохід списком змінює й зберігає інтервал зміни сцен (аналогічно idle — може ввімкнути автоперехід у режим спокою);
  (в) повзунок гучності при русі вниз пропускається (після `ambience` одразу `rotation`).
  Існуючий check «D-pad reaches settings 12/12» цього не ловить.
- Мінімальний фікс: для `SELECT` змінювати значення ←/→ (як уже зроблено для `range`, `app.js:141`),
  а ↑/↓ віддати просторовій навігації. Додати в `browser_checks.js` прохід ↓ до останнього пункту з
  перевіркою, що prefs не змінились.

### P1-2. «Увімкнути атмосферу» після перезавантаження **вимикає** звук
- Код: `app.js:127` (і `app.js:132` для пульта) — якщо `prefs.audio` збережено `true`, перший жест робить
  `unlockAudio()`; одразу після цього `action()` для `data-action="audio"` (`app.js:118`) інвертує `prefs.audio` → `false`.
  При цьому до розблокування label показує «Увімкнути атмосферу» (`app.js:43`), хоча prefs.audio=true.
- Відтворення: `prefs.audio=true` у localStorage → reload → label «Увімкнути атмосферу» → клік →
  `{label:"Увімкнути атмосферу", stored:false, audio-on:false}`. Користувач натиснув «увімкнути» — звук вимкнувся і це збереглось.
- Мінімальний фікс: у `case 'audio'` — якщо `prefs.audio && !audioUnlocked` (до цього кліку), лише розблокувати
  (не інвертувати); або в глобальному обробнику не робити auto-unlock, коли ціль — сама кнопка audio.
  Додати `aria-pressed` на `.audio-invitation` і чесний label увімкненого стану (напр. «Атмосфера увімкнена»).

## P2 — підтверджені дефекти / суттєві недоліки

### P2-1. Hover миші переносить chakra-печатку, але не фокус — OK запускає інший застосунок
- Код: `app.js:172` (`pointerover` → `updateFocus(card)` без `focus()`), `style.css:4` `.app-card:focus-visible{outline:none}`.
- Відтворення: фокус на SmartTube, `pointerover` на Netflix → печатка й `is-focus` на Netflix,
  `activeElement` = SmartTube; Enter → тост «SmartTube — у макеті…». Справжній фокус лишається без жодного індикатора.
  FC04 «та сама семантика фокуса… без втрати keyboard selection» — порушено.
- Фікс (один рядок): у pointerover робити `card.focus({preventScroll:true})` (тоді печатка = фокус),
  або повертати печатку до `document.activeElement` на першу стрілку/Enter.

### P2-2. Шари звуків змішуються: майже кожна дія = confirm/back **+** focus-swipe
- Код: `app.js:171` грає `focus` на кожен `focusin` кнопки, включно з програмним фокусом після
  `openPanel` (`app.js:80`), `closePanel` (`app.js:82`), pin (`app.js:120`), вибору сцени з панелі.
- Виміряно: open panel → `[chakra-confirm, chakra-focus]`; Escape → `[scroll-back, chakra-focus]`.
  Back втрачає «впізнаваний інший тембр» (AU03), бо одразу накривається swipe.
- Фікс: прапорець `suppressFocusSound` на програмні `focus()` (або грати focus лише в `remote()`/pointer-навігації).

### P2-3. Японський підпис сцени перекриває обличчя Naruto на TV-viewport
- Код: `style.css:4` `.scene-caption{position:absolute;right:0;bottom:36px…}`; на 1280×720 bbox caption
  `x 1045–1227, y 241–343`. Скріни `verification/candidate-chakra-focus.png`, `candidate-home-960.png`
  і мої night/dawn 1280: «木ノ葉隠れの里» лежить на підборідді/щоці Naruto у всіх трьох сценах.
  На 1920 — лише на торсі (ок). Порушує принцип TX02 «текст не перекриває обличчя».
- Фікс: на `max-height:800px` перенести caption нижче (над scene-strip) або ліворуч від персонажа / зменшити.

### P2-4. Перекриття hero-kicker з brand на 1280×720
- Виміряно: `.hero-kicker.top = 64.25`, `.brand.bottom = 70`; `.hero-copy` 321px > `.hero` 309.6px,
  `align-items:center` (`style.css:4` `.hero`) виштовхує копію вгору в topbar. Видно на
  `candidate-chakra-focus.png`: «Твій прихований світ / Село, приховане в листі» злипаються.
  На 960×540 зазор лише 5px (`candidate-home-960.png`).
- Фікс: у `@media(max-height:800px)` (`style.css:7`) `.hero{align-items:flex-end}` або прибрати kicker / зменшити `h1`.

### P2-5. Дрібна типографіка для 10-foot UI на 960×540
- Виміряно на 960×540 (саме цей viewport проєкт називає TV): brand subtitle 7px; дата, `Вечірній вітер`,
  footer-hints, «Локальний макет» — 8px; scene-кнопки, kicker, «Увімкнути атмосферу» — 9px;
  **назви застосунків і обидві hero-CTA — 10px**. При DPR 2 це ~10dp < 12sp мінімуму Android TV.
  Джерела: `style.css:7` (`.app-name 12px`, `.app-meta 8px`), `:8` (`.app-name 11px`), `:11` (CTA 10px).
- Фікс: мінімум ~12px CSS для функціональних підписів у TV media queries (назви app, CTA, scene choices);
  декоративні (kicker, footer) — можна залишити або сховати.

### P2-6. На TV фон фактично статичний: parallax лише від миші
- Код: `app.js:173` — `--px/--py` змінюються тільки на `pointermove`; `.backdrop` має постійний `scale(1.035)` (`style.css:4`).
  З пультом панорама ніколи не рухається; динаміка = 2 розмиті radial-blob «хмари» (opacity .08–.13),
  «glow» справа (`lantern-breathe`) і 28 canvas-листків. «Chakra sparks / wind streaks» (BG05) у коді немає.
  Хмари `cloud-drift` лінійно стрибають на старт кожні 90/120 с (`style.css:5`), хоч і ледь помітно через blur.
- Це не баг коду, а розрив із брифом «dynamic scenery / separate motion layers» саме на цільовому пристрої.
- Мінімальна рекомендація: часовий повільний drift `--px/--py` (синус 40–60 с, ±6–10px) коли немає pointer;
  можливо, focus-центр як легкий parallax-сигнал. Без нових assets.

### P2-7. Ambience loop «дихає» тишею кожні 24 с
- Код: `tools/generate_audio.py:26` `fade=min(1,t/2,(24-t)/2)` → на шві loop гучність 2 с падає до 0 і 2 с росте.
  Через `air.loop=true` (`app.js:36`) це регулярний провал кожні 24 с — помітний у тихому фоні.
- Фікс: seamless loop (crossfade кінця в початок при синтезі) замість fade-in/out.

## P3 — дрібні дефекти / підказки

1. **Стара точка trail.** `hideFocus()` (`app.js:161`) не скидає `focusCenter`. Відтворено: фокус на картці
   в бібліотеці → Escape (фокус на «Мої застосунки») → фокус на dock → trail `[879,550 → 129,556]` летить з
   місця закритої модалки. Той самий артефакт видно на `candidate-chakra-focus.png` (лінія з центру екрана).
   Фікс: `focusCenter=null` у `hideFocus`.
2. **Немає початкового фокуса.** На старті `activeElement=body`, печатки немає; перший ↓/→ фокусує `brand`
   (`app.js:146`), до першої програми — 4 натискання. Для лаунчера доцільно фокусувати перший dock-елемент.
3. **Library відкривається з фокусом на «×»** (`app.js:80`), не на пошуку/першій картці.
4. **Pin 7-го застосунку** додає його в кінець (`app.js:120`), у dock видно лише перші 6 (`app.js:73`) — на
   головній нічого не змінюється, фідбеку немає. Тост «Обране: 7 — у dock видно перші 6».
5. **`YoruPause` не зупиняє `rotationTimer`/`idleTimer`** (`app.js:184`); у native onPause без `document.hidden`
   ротація продовжує `setScene`+`persist`. Звук блокує `paused`, але таймери варто чистити.
6. **Повернення фокуса губиться** при відкритті панелі з панелі (ContextMenu в бібліотеці, «До налаштувань»
   з «Про»): `lastFocus` стає елементом панелі, після закриття — фокус на `brand` (`app.js:77`, `:82`).
7. **Crossfade без preload**: `setScene` одразу додає `.shown` (`app.js:51`); на повільному WebView перші
   секунди фейду можуть показати плоский `#14323c`. `img.decode()` перед `.shown` — дешеве страхування.
8. Типи prefs з localStorage не валідуються для boolean (`app.js:22`), напр. `"false"` → truthy. Некритично.

Безпека: проблем, значущих для прототипу, не знайдено — `escapeHTML` на всіх даних застосунків
(`app.js:69-70,95`), `innerHTML` лише зі статичних рядків, CSP `script-src 'self'`, сервер на `127.0.0.1`.
Reduced motion: перевірено — canvas зупинено (`frame=0`), CSS-анімації/transition backdrop = none, печатка лишається статично видимою. ✔
Чесність Android-дій: launch/system/Wi-Fi у preview дають явний тост; about-панель і README не обіцяють APK. ✔

## Топ-3 художні покращення (у межах брифу)

1. **Підпис сцени — з обличчя на «камінь».** Перенести `木ノ葉隠れの里` вертикально (writing-mode: vertical-rl)
   у ліву частину Hokage Rock або над scene-strip — і обличчя вільне, і це сильніший японський мотив.
2. **Жива панорама без миші.** Повільний часовий drift + 2–3 точкові мерехтіння саме на ліхтарях панорами
   (координати фіксовані, бо композиція всіх трьох сцен однакова) — дає «dynamic scenery» на TV без нових raster.
3. **Spotify-емблема читається як TV/Wi-Fi** (антени + дуги на екрані, `design/icon-board.jpg`). Лишити жабу,
   але прибрати антени/рамку телевізора, щоб три sound-arcs були головним силуетом.
