# 2026-11-11: Налаштування Orca Mobile Emulator, створення Parity Studio та усунення розбіжності Расенсюрікена

## 1. Контекст і запит Майстра Іллі
1. Використати вкладку Mobile Emulator в Orca для візуального контролю та дебагу без необхідності щоразу встановлювати APK на телевізор Lenovo.
2. Налаштувати окреме порівняння двох технік без усього лаунчера (ізольований режим).
3. Визначити й усунути першопричину, чому анімація Расенсюрікена все ще виглядала не так, як в еталоні.

---

## 2. Діагностика Orca та середовища хоста
- **Діагностика CPU хоста:** AMD Ryzen 5 3600 має `VirtualizationFirmwareEnabled: False` (SVM вимкнено в BIOS материнської плати). Через це локальний віртуальний емулятор Android Studio (QEMU/WHPX) не запускається без увімкнення SVM в BIOS.
- **Підключення пристрою до Orca:** Orca Mobile Emulator використовує `scrcpy` для трансляції екрана будь-якого підключеного Android-пристрою.
- Виконано прив'язку: `adb connect 192.168.100.26:5555` та `orca emulator attach "192.168.100.26:5555"`.
- Зареєстровано потік `scrcpy://192.168.100.26:5555`. Для активації вікна в UI Orca користувачеві достатньо перевести тумблер "Enable Mobile Emulator" у положення ON.

## 3. Створення ізольованої лабораторії порівняння (`prototype/compare.html`)
Створено повнофункціональну інтерактивну сторінку для 1:1 порівняння технік у браузері Orca:
- **Шлях:** `NarutoLauncher/prototype/compare.html` (відкрито в Orca: `http://localhost:8085/prototype/compare.html`).
- **Склад:**
  1. Панель 1: Веб-еталон (`technique-art.js`).
  2. Панель 2: Android Native Port (`TechniqueRenderer.java`).
  3. Панель 3: Теплова карта різниці (Absolute Pixel Diff) з метрикою розбіжності.
- **Керування:** вибір техніки, пауза, покадровий крок (16.6ms), повзунок швидкості (0.1x–2.0x), тумблери шарів (Core, Plate, Accents, Fallback).

## 4. Першопричина та виправлення Расенсюрікена
1. **Геометричне перекриття карткою:**
   - В еталоні картка має прозорий фон (`rgba(0,0,0,0)`), а радіус сюрікена становить $r = 82.6\text{ px}$ (діаметр 203 px).
   - На Android `ChakraFocusView` використовував коефіцієнт $0.45$, що давало радіус лише $54.6\text{ px}$ (діаметр 134 px). Картка розміром 92x92 px перекривала 80% площі лопатей вітру.
   - **Виправлення:** у `ChakraFocusView.java` збільшено базовий коефіцієнт до $0.68$, встановивши точний радіус $82.5\text{ px}$ (діаметр 203 px).
2. **Фазовий зсув дуг `accents()`:**
   - В еталоні `ctx.ellipse` починає дугу з кута $a$. В Android `drawArc` використовувався кут `0f`.
   - **Виправлення:** у `TechniqueRenderer.java` передано кут `Math.toDegrees(a)`.
